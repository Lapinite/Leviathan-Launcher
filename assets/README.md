## Recommended Image Naming

Use simple lowercase filenames with hyphens.

Examples:

```text
logo.png
icon.png
banner.png
social-preview.png
wordmark.png
home.png
login.png
profiles.png
settings.png
launcher.png
```

Avoid filenames such as:

```text
final-final2.png
newlogo123.png
screenshot(4).png
```

---

## Recommended Formats

Preferred formats:

- `PNG` for logos, icons, UI screenshots, and transparency
- `SVG` for vector branding where appropriate
- `WEBP` for large screenshots when file size matters
- `JPG` only for photographic artwork without transparency

For logos and icons that need transparency, prefer PNG or SVG.

---

## Recommended Sizes

Suggested sizes:

### Icon

```text
1024 × 1024
```

Keep important artwork away from the edges so circular crops work correctly on GitHub, Discord, and similar services.

### GitHub Social Preview

Recommended target:

```text
1280 × 640
```

### Banner

Recommended wide formats:

```text
1920 × 600
1920 × 720
2560 × 800
```

### Screenshots

Use the launcher's native UI resolution where possible.

Avoid excessive compression that makes text difficult to read.

---

## File Size

Keep repository assets reasonably optimized.

For small icons and profile pictures, aim for well under 1 MB where practical.

Large screenshots or banners should be compressed appropriately before committing.

Avoid committing unnecessarily huge source-art files to the main repository.

---

## Source Artwork

Editable source artwork such as:

- PSD
- AI
- Blender projects
- Large layered image files
- Raw design exports

should generally be kept separate from normal repository assets unless there is a clear reason to publish them.

The `assets/` folder should primarily contain final exported assets intended for documentation, branding, or review.

## Adding New Assets

When adding a new asset:

1. Place it in the correct subfolder.
2. Use a clear filename.
3. Optimize the file size.
4. Preserve transparency where required.
5. Update project documentation if the asset is referenced publicly.
6. Confirm that the project has the right to publish the asset.
